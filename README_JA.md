# 墨影 MoYing 🎬📚

[简体中文](./README.md) | [English](./README_EN.md) | **日本語**

**ダーク / ライト両テーマ**対応の読書・映画記録アプリ（Flutter 製、データはローカル永続化、
オフラインファースト —— オンライン検索はオプションの拡張機能です）。

下部の 4 タブで構成：**ダッシュボード / 書籍 / 映画 / 個人**。

- **ダッシュボード**：統計カード 2 枚（読書の平均進捗リング + 映画の平均評価バッジ）、進行中タスクの
  横スライド、読書リストと映画グリッド（各 4 件、「すべて見る」で全量へ）
- **書籍 / 映画**：検索 + 動的フィルタ + リスト / グリッド切替。カードをタップで詳細、
  長押しで編集。詳細ページにはキャスト & スタッフ一覧やスチールギャラリーがあり、
  俳優ページから出演作品を逆引きできます
- **個人**：ニックネーム / 署名 / アバター編集、テーマ三択（ダーク / ライト / システムに従う）、
  統計、データソース管理、クラウド同期、エラーログ

v0.9.0 以降、初回起動は**空のライブラリ**から始まり、記録はユーザー自身が追加します。
以降の追加・編集・削除はすべてローカルに永続化されます。（デモ用シードデータはテストのみに保持）

## 実行方法

```bash
# 本リポジトリは Flutter 3.24.x（3.24.5 を含む）で検証済み
flutter pub get
flutter run            # 対象デバイスを選択（Android / iOS / macOS）
```

> ネットワーク制限のある環境では、まずミラーを設定してください：
> ```bash
> export PUB_HOSTED_URL=https://pub.flutter-io.cn
> export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
> ```

Android APK のビルド：

```bash
flutter build apk --release
# 生成物：build/app/outputs/flutter-apk/app-release.apk
```

## 検証

```bash
flutter analyze       # 静的解析（CI は --fatal-infos で実行、0 issue を期待）
flutter test          # ユニット & widget テスト（現在 35 ファイル、490 ケース）
```

CI（`.github/workflows/ci.yml`）は `main` への push / PR ごとに
`flutter analyze --fatal-infos` → `flutter test` → `flutter build web` を順に実行します。

> **対応プラットフォーム**：**Android / iOS / macOS が主要ターゲット**です ——
> 永続化・画像管理・バックアップ・WebDAV 同期はいずれも `dart:io` のローカルファイルシステムに依存します。
> Web ターゲットは**ビルド可能**（CI がビルドします）が、ローカルファイルシステムが無いため
> `persistence_stub.dart` が純メモリ保存にフォールバックし（リロードで消失）、
> ログの永続化・エクスポート（`log_sink_stub.dart` / `log_exporter_stub.dart`）は no-op に低下、
> 画像 / バックアップ / 同期の入口はプラットフォームに応じて非表示または低機能化されます。
> つまり「UI は動くが、正式な利用プラットフォームにはならない」位置づけです。

## アーキテクチャ

**四層コンポーネント化 + MVVM** を採用。依存の方向は厳格に一方向 ——
**上位層は下位層に依存でき、逆は禁止**：

```
app (5)  →  business {shared カーネル} (75)  →  component (9)  →  foundation (16)
```

| 層 | 責務 | 依存可能 |
|---|---|---|
| `app/` | アプリ層：グローバル設定（テーマ / 遷移 / タイポグラフィ）、ルートコンテナ、**グローバルルートテーブル** | 下位の全層 |
| `business/` | ビジネス層：**モジュール**単位で分割、モジュール内は MVVM；`shared/` はモジュール横断の共有カーネル | `shared` / `component` / `foundation` |
| `component/` | 再利用 UI コンポーネントとデザイントークン | `foundation` |
| `foundation/` | ログ / ネットワーク / ストレージ / ユーティリティ / **ルート名・共通文案の定数**。業務モデルを知らない | なし |

**ハードルール**：

1. **page 命名**：必ず `xxx_page.dart` → クラス `XxxPage`。
2. **view 命名**：機能で命名（`xxx_card.dart` / `xxx_sheet.dart` / `xxx_picker.dart`）。
   ファイル名・クラス名に **`widget` キーワードは禁止**。
3. **デザイントークン**は `component/theme/app_palette.dart`；フォントサイズ階層は
   `app/config/app_typography.dart`（`AppType`、新規コードで使用、既存は触れた際に移行）。
4. `foundation/` は `business/` のいかなるシンボル（model を含む）も import してはならない。
5. `component/` は `business/` を import してはならない。業務機能が必要な場合は、
   コンポーネント層で**契約 + InheritedWidget** を宣言し、app 層が `MaterialApp` より上で
   実装を注入する（`component/media/local_media_scope.dart` を参照）。
6. **ビジネスモジュール間の直接参照はゼロ**（v0.9.3 で達成）。モジュール間の連携は次の 2 経路のみ：
   - `business/shared/` の共有カーネルに依存：純 DTO（`model/`）、共有リポジトリ
     （`repository/library_store.dart`）、ファサードインターフェース（`library_facade.dart` /
     `data_source_facade.dart`）、純粋ユーティリティ；
   - モジュール横断の遷移は `Navigator.pushNamed(AppRoutes.xxx)` で行う（ルート名定数は
     `foundation/constants/app_routes.dart`）。**ページ構築は `app/router.dart` に集約**し、
     兄弟モジュールの Page クラスを import することは禁止。
7. **ファサード登録**：`LibraryProvider` / `DataSourceProvider` はそれぞれ `LibraryFacade` /
   `DataSourceFacade` を実装。app 層は `ListenableProvider<ファサード>.value` で
   **同一インスタンス**を登録する（`Provider` ではなく `ListenableProvider` を使う ——
   通知を購読するのは前者だけで、`context.select` の再構築はそれに依存する）。

    ├── constants/                     # app_routes（ルート名）/ app_strings（横断文案）
    ├── logger/                        # ログ基盤：レベル + リングバッファ + 直列化書き込み + 2MB ローリング
    │                                  #   （io / stub をプラットフォームで配線）+ エクスポート（io / stub）
    ├── network/                       # cover_headers（Referer）/ http_retry（レイヤー化タイムアウト + リトライ）

## 機能メモ

- **ダーク / ライト両テーマ**：パレットは `ThemeExtension` で注入し、色の取得は必ず
  `context.colors.xxx` 経由。ダークがオリジナルデザイン（背景 `#0F0F0F` / カード `#1A1A2E`）、
  ライトはその反転（白に近い背景 / 純白カード / 濃いグレーの文字）。テーマ設定は `profile.json` に
  保存され再起動後も保持、「システムに従う」も選択可。
- **カバーの縮退表示**：ローカル画像とネットワーク画像に対応。カバーが無い・読み込み失敗の場合は
  HSL グラデーション + 文字マークのプレースホルダーにフォールバックし、オフラインでも
  レイアウトが崩れません。
- **状態管理**：Provider（`ChangeNotifier`）を単一のデータソースとし、UI は読み取りのみ、
  書き込みは Provider が一括で永続化。一覧ページは `context.select` で購読を絞り、
  無関係な rebuild を回避。モジュール横断の消費はファサードインターフェース
  （`LibraryFacade` / `DataSourceFacade`）経由 —— 兄弟実装ではなく抽象に依存します。
- **円形プログレスリング**：`CustomPainter` + `SweepGradient` + 900ms のイージングアニメーション。
- **入力候補**：書籍カテゴリも映画ジャンルも「候補の選択 + 自由入力」の複数選択タグ；
  映画の監督はフォーカス喪失時に自動でキャスト欄の先頭に追加。
- **エラーログ**：レベル別の記録 + メモリリングバッファ（500 件）+ 2MB ローリング永続化、
  起動時に履歴を読み戻すため「前回起動時にクラッシュした」情報も次回確認できます。
  **記録するのはエラー / 警告 / クラッシュとリクエスト失敗のみ。閲覧行動は記録せず、
  データは一切アップロードされません。** プライバシー制約の詳細は `AppLogger` の
  ドキュメントコメントを参照。

## 実装済み

- **ローカル永続化**：JSON ファイル保存（`LibraryStore`）、アトミック書き込み（`.tmp` + rename）、
  `schemaVersion` 検証、同一 tick 内の複数書き込みの自動マージ、並行上書きを防ぐ
  書き込みチェーンの直列化；ユーザープロフィールは独立した `profile.json`
- **書籍 / 映画 / 俳優のフル CRUD**：3 種の編集ページ + 詳細ページ；映画に参照されている俳優は
  削除が拒否され、参照元の作品が一覧表示されます
- **検索とフィルタ**：キーワード検索、カテゴリ / ジャンル / 状態のドロップダウンフィルタ
  （選択肢は既存データから動的に生成、ユーザー定義値を含む）。詳細ページで著者をタップすると
  フィルタに事前入力した状態でライブラリへ遷移
- **画像管理**：ギャラリーから選択 / ネットワーク URL 貼り付け / カバーの削除に対応。画像は
  アプリのプライベートディレクトリにコピーし、上限内に圧縮して保存。差し替え・削除時には
  孤児ファイルを自動回収
- **キャスト & スチール**：映画詳細ページの「キャスト & スタッフ」からグループ化・検索可能な
  一覧を開く；「スチール → すべて」でタブ切替のスチール & ポスター全量ページへ。スチールは
  ディスクにキャッシュされ、再訪時のネットワーク要求はゼロ。俳優をタップすると俳優ページから
  出演作品をすべて逆引き
- **実データ連動のダッシュボード**：統計カード 2 枚、進行中タスク、読書 / 映画グリッドはすべて
  ライブラリデータからリアルタイム計算、空状態のフォールバック付き。ライブラリが空の場合、
  空状態カード全体がタップ可能で「書籍を追加 / 映画を追加」へ直行；「すべて見る」は対応タブへ遷移
- **個人センター**：ニックネーム / 署名 / アバター編集（アバターカードのタップは閲覧のみ、
  「プロフィール編集」行で編集）、統計ページ、テーマ三択
- **三セクション型ダッシュボード統計（個人統計ページ）**：上部に年間指標バー
  （年間 X 冊・Y 本・視聴 Z 時間）+ GitHub 風ヒートマップ（30 日 / 四半期 / 年切替。
  カウント規則は「同一エンティティは同日 1 回のみ、異なるエンティティは加算」。0 / 1 / 2 / 3+ の
  4 段階着色。書籍の createdAt / startedAt / finishedAt と映画の watchDate を集計）。
  中部にカテゴリ選好のドーナツ図（Top5 + パーセンテージ凡例）と 1〜5 星の評価分布棒グラフ
  （いずれも純 `CustomPainter`、サードパーティ依存ゼロ）。下部に読書進捗バー
  （既定 3 冊 + 「すべて見る」シート）、年間五つ星カバーウォールと年間レポート入口。
  各セクションに空状態の案内付き
- **年間レポート**：年間スナップショットページ（`annual_report_page.dart`）—— 年間サマリーの
  グラデーションカード（読了冊数 / ページ数 / 視聴時間 / 年間の選好カテゴリ）、最も遅く読み終えた本、
  最も多くページを読んだ週、習慣を破った一冊（その年の読了書で、カテゴリが全体の最頻値と異なるもの）。
  データはリアルタイム計算、記録の変化で即時更新
- **同期 / バックアップ**：WebDAV クラウド同期（坚果云・Nextcloud などの標準 WebDAV）——
  サーバー設定 4 項目 + 接続テスト、即時バックアップ / クラウドからの復元（復元前の二重確認 +
  ローカルスナップショットによる保険）、起動時の自動同期（Wi-Fi のみに制限可、1 時間に 1 回へ
  スロットリング）、バックアップにはローカル画像を含められます（単一 JSON / 画像入り ZIP）。
  端末間の衝突は**レコード単位の LWW マージ**で解決（id で和集合、新しい `updatedAt` が勝つ）。
  マージ前後それぞれにローカルスナップショットを残し、ロールバック可能。ローカルエクスポートは
  「保存先ピッカー」を表示してユーザーが保存先を選択（画像を含むかは同期設定に追従：
  ON → ZIP、OFF → JSON）。オフライン環境の最後の手段です。認証情報は OS のセキュアストレージ
  （Keystore / Keychain）に保存され、`settings.json` にパスワードは含まれません。Web では
  この機能の入口を非表示
- **オンライン情報補完（オプション）**：個人センターの「データソース管理」—— 映画は TMDB 内蔵、
  書籍は OpenLibrary（既定）と Google Books 内蔵。**サードパーティサイトの追加に内蔵プリセットは不要**：
  カスタムデータソースに Base URL と API キーを入力すれば、返却 JSON をスマート解析が処理します
  （データ配列を再帰的に探索 + 中英フィールド別名マッピング、配列 / `{data:[…]}` / `{results:[…]}`
  などの一般的な構造に対応）。douban・Bangumi などのサイトはこの経路で接続できます。ページ内には
  「セルフホスティングガイド」（GitHub + Render の無料ホスティング例を含む Markdown チュートリアル）
  もあります。複数のソースを追加して 1 つを既定にでき、接続テストと設定編集に対応。
  書籍 / 映画編集ページ上部の「クイック検索」に名称を入力するとオンライン検索
  （500ms デバウンス + TTL/LRU 結果キャッシュ）。結果を選ぶとフォームに自動入力
  （書籍は ISBN とカバー、映画は監督 / 主演 / 上映時間 / ジャンル / ポスター）。
  保存時に出典 `source` を記録。書籍検索は**マルチソース集約**（重複排除マージ + カテゴリの
  中国語変換）。カバー要求は Host ごとに `Referer` を付与してホットリンク対策を回避し、
  ミラーフォールバック・レイヤー化タイムアウト・1 回リトライを備えます。TMDB の API キーは
  セキュアストレージに保存。データソース設定は `data_sources.json` としてバックアップ / 復元に
  含まれます（schemaVersion 2、後方互換）。クラウド復元後は自動で再読み込みし、認証情報が欠けている
  ソースを一覧表示します。未設定・オフライン時は検索ブロックが自動で隠れ、手入力には影響しません
- **エラーログ（個人 → エラーログ）**：レベル / 分類別にアプリのエラーとリクエスト失敗を記録。
  全域の未捕捉例外（フレームワーク + 非同期）、ネットワークリトライの枯渇、データソース取得失敗、
  同期・バックアップの異常をカバー。ページではレベル別統計、新しい順の一覧、**エクスポート**
  （ローカル `.txt` に書き出してシステム共有へ）、**全コピー**（クリップボード）、**クリア**（二重確認）
  を提供。データは端末内にのみ存在し、ユーザーが能動的にエクスポートして開発者へ渡すかどうかを
  決められます

## 開発規約

- **依存の方向**：`app → business → component → foundation` の一方向を厳守。
- **モジュール分離**：ビジネスモジュール間の直接参照はゼロ —— モジュール横断のデータ依存は
  `business/shared/`（DTO / リポジトリ / ファサード）経由、モジュール横断の遷移は `AppRoutes` の
  ルート名で行う（ページ構築は `app/router.dart` に集約）。兄弟モジュールの page / view_model の
  import は禁止。
- **色の取得**：必ず `context.colors.xxx`、静的定数色は禁止（テーマ切替時に const サブツリーは
  再描画されないため）。フォントサイズは新規コードで `AppType` 定数を使用。
- **命名**：ページは `XxxPage` / `xxx_page.dart`；ビューコンポーネントは機能で命名し、
  `widget` キーワードは禁止。
- **テストの同時変更**：`LibraryStore`、マージエンジン、データソース解析などの中核ロジックを
  変える場合はテストも同時に追加。変更の合否基準は `flutter analyze`（0 issue）と
  全量 `flutter test` のグリーン。
- **フォーマットゲート**：CI の `dart format --set-exit-if-changed` は既定でコメントアウト。
  有効化する場合は、まずローカルで `dart format .` を実行してから
  `.github/workflows/ci.yml` の該当ステップのコメントを外してください。
